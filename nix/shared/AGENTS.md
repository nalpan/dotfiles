# 言語

- 会話は日本語で行うこと
- 技術的用語は日本語訳せず、英語のまま出力すること

# 文書の作り方

- 結論→詳細の構成にすること
- MECEにし、冗長さを排除すること
- 複雑な概念の説明などは図を活用すること

# 調査と結果報告のルール

- 調査は必ず1次ソースを探すこと
- 結果報告では事実と考察を分けて報告し、報告の元となる資料やそのURLを提供すること

# 実装について

- TDDで実装し、red → green → refactor を **厳守** すること
- シグネチャの命名は具体的なドメイン知識を表現すること
- コメントは1行で簡潔に留めること、実装や処理の詳細は書かない

# 計画の作り方

原則以下のようにしてください、別途指示があればその指示を優先すること

- 目的が達成されていることの検証作業も含むこと
- コミット単位も考慮した計画にすること

# ブラウザ操作

- playwright-cli または Playwright MCP を利用すること

# Gitの操作

- コミットメッセージは日本語で記述すること
- コードベースの変更はworktreeを作成し行うこと

# GitHubの操作

- GitHubを操作するときは、`gh` コマンドを利用すること
- Pull Requestを作成する際は**必ず**draftにすること
- push 時は PR 本文を修正すること
- PR コメントへは返信しないこと
- PR description には設計結果を図や表で記述すること
- PR description にはなぜこの設計を取ったのかを記述し、なぜこの設計を取らなかったのかは**記述しない**こと

## PR の作り方

- 1PRの変更行数は400行以内とすること
- 1PRの変更行数が400行を超えないといけないときは相談すること
- PRの説明は「変更の背景」「推奨するレビューの順番」「行った検証」の3つとすること
